1. EXECUTIVE SUMMARY & THE CORE PROBLEM
--------------------------------------------------------------------------------
1.1 Hackathon Context & Philosophy
* Built for a 24-hour sprint addressing emergency humanitarian logistics during
  catastrophic infrastructure blackouts.
* Guiding Philosophy: "Zero-connectivity resilience, zero hallucinated aid,
  zero-knowledge privacy."
* Target Users: Disaster victims, volunteer squads, institutional NGOs, CSR
  units, and emergency dispatch commanders.

1.2 The Disaster Bottlenecks
* Total Grid & Telecom Collapse: 4G/5G mobile data and fiber connectivity drop,
  rendering web dashboards and heavy mobile applications inoperable.
* Uncoordinated Organizational Silos: Relief organizations manage fragmented
  spreadsheets, resulting in simultaneous hoarding and critical stockouts.
* Hallucination Risks in Autonomous AI: Standard LLM-based logistics tools invent
  non-existent supply counts, double-book inventories, and create invalid routes.
* Vulnerability & Privacy Exploitation: Broadcasting unencrypted victim locations,
  medical details, or identities over open channels exposes displaced populations
  to predatory targeting and hoarding.

3. ULTRA-COMPRESSED CODEC & PACK10 GEOLOCATION SPECIFICATION
--------------------------------------------------------------------------------
3.1 Requester Frame Specification (10 Characters Base-36)
Pos 0: Schema Version ('1' = Requester v1)
Pos 1: Situation Type (0-9, A-B: Flood, Earthquake, Building Collapse, Fire, etc.)
Pos 2: Headcount Bucket (0=1 person, 1=2, 2=3-4, 3=5-8, 4=9-15, 5=16-30, etc.)
Pos 3: Injury Severity (0=None, 1=Minor, 2=Serious/Non-ambulatory, 3=Critical)
Pos 4: Mobility / Entrapment (0=Mobile, 1=Impeded, 2=Trapped Debris, 3=Waterbound)
Pos 5: Urgency Level (L=Low, M=Medium, H=High, C=Critical)
Pos 6-8: Needs Bitfield (12 bits base-36: Food, Water, Medical, Tents, Rescue, etc.)
Pos 9: Vulnerability Bitfield (5 bits: Infants, Elderly, Pregnant, Disabled, Chronic)

3.2 Provider Offer Frame Specification (9 Characters Base-36)
Pos 0: Schema Version ('2' = Provider v1)
Pos 1: Organization Type (NGO, Gov, CSR, Local Volunteer, Military)
Pos 2-4: Resource Inventory Bitfield (Matches Requester 12-bit taxonomy)
Pos 5: Capacity Volume Bucket
Pos 6: Service Radius Bucket
Pos 7: ETA Availability Bucket
Pos 8: Status Flag (A=Available, L=Limited, U=Unavailable)

3.3 PACK10 High-Precision Geolocation Codec
* Eliminates heavy float coordinates and external base32 geohash dependencies.
* Encodes Global GPS Coordinates down to ~1.1-meter precision in 10 characters.
* Encoding Formula:
    lat_offset = round((latitude + 90.0) * 100000)
    lon_offset = round((longitude + 180.0) * 100000)
    lat_token  = base36_encode(lat_offset) padded to 5 characters
    lon_token  = base36_encode(lon_offset) padded to 5 characters
    PACK10_GEO = lat_token + lon_token

* Worked Coordinate Verification:
    Lat: 23.25991  -> Offset: 11325991 -> Base-36: 6QR6V
    Lon: 77.41263  -> Offset: 25741263 -> Base-36: FBQ33
    Combined PACK10: 6QR6VFBQ33

3.4 Complete Unified Wire Frame
* Example Payload:
    Q|001|7F3K|15223C03Q0|6QR6VFBQ33|7F
* Frame Fields:
    [TYPE]     : Q (Individual Emergency Request)
    [SEQ]      : 001 (Monotonic message sequence)
    [UID]      : 7F3K (First 4 chars of sha256(device_install_id))
    [PAYLOAD]  : 15223C03Q0 (10-char Base-36 crisis state)
    [PACK10]   : 6QR6VFBQ33 (Encoded 1.1m GPS coordinates)
    [CHECKSUM] : 7F (2-character hexadecimal XOR checksum)
* Character Budget: Exactly 35 GSM-7 characters (125 characters spare in standard SMS).

def calculate_xor_checksum(text: str) -> str:
    """Calculates 2-digit uppercase hex XOR checksum over raw ASCII frame."""
    val = 0
    for char in text:
        val ^= ord(char)
    return format(val, "02X")

MULTI-AGENT REASONING PIPELINE & DETERMINISTIC BOUNDARIES

5.1 Agent Roles & Implementation Rules

    A0 (Intake): Pure Python. Strips whitespace, parses pipe delimiters, verifies XOR.

    A1 (Dedupe): Pure Python. MongoDB unique compound index on (uid, seq).

    A2 (Triage): Groq / Llama 3.3 70B. Evaluates situational risk into priority rank.

    A3 (Geo Matcher): Pure Python + MongoDB. Runs $geoNear on 2dsphere spatial index.

    A4 (Advocates): Groq / Llama 3.3 70B. Parallel prompt simulating provider stances.

    A5 (Solver): Pure Python. Linear/Greedy inventory optimizer. Generates exactly
    3 fixed plan options: 'fastest', 'max_coverage', 'least_depleting'.

    A6 (Arbiter): Groq / Llama 3.3 70B. Evaluates A4 arguments and outputs Pydantic
    schema containing only { "selected_option_id": "fastest", "reasoning": "..." }.

    A7 (Redactor): Pure Python. Masks identity/GPS for zero-knowledge privacy.

    A8 (Admin Gate): Pure Python. asyncio.Future interrupt with Autopilot timeout.

    A9 (Narrator): Groq / Llama 3.3 70B. Emits plain-English live logs for dashboard.

    A10 (Verification): Pure Python. Validates digital handshakes and field acks.

    A11 (Replanner): Pure Python Trigger. Re-enters at A3 upon delivery failure.

5.2 The Hallucination Firewall Principle

    The LLM is strictly prohibited from generating, dividing, or updating numeric
    quantities in the database.

    Python executes all mathematical operations (A5 Solver). The LLM functions
    strictly as an evaluator, ranking engine, and plain-English narrator.

    TERMUX ROOTLESS SMS GATEWAY IMPLEMENTATION

6.1 Overview & Architecture
Turn any Android phone with an active SIM card into an automated SMS gateway
without root access using Termux and the Termux:API add-on.

6.2 Setup Steps on Android

    Install Termux and Termux:API from F-Droid.

    Grant Permissions in Android Settings:

        SMS (Send and view SMS messages)

        Phone State

        Disable Battery Optimization for Termux & Termux:API (Set to Unrestricted).

    Inside Termux, run:
    pkg update -y && pkg install termux-api python -y
    pip install requests
    termux-wake-lock
    #!/usr/bin/env python3
import subprocess
import json
import time
import requests
import sys

# Configure Laptop Local IP (Phone & Laptop must share Wi-Fi or Mobile Hotspot)
BACKEND_URL = "[http://192.168.1.50:8000/api/v1/sms/webhook](http://192.168.1.50:8000/api/v1/sms/webhook)"
POLL_INTERVAL = 2
PACT_HEADERS = ("Q|", "G|", "N|", "R|", "S|", "C|", "M|", "P|", "RT|", "X|")

def get_incoming_sms():
    try:
        res = subprocess.run(["termux-sms-list", "-l", "3"], capture_output=True, text=True, check=True)
        return json.loads(res.stdout)
    except Exception as e:
        return []

def forward_to_backend(payload, sender):
    try:
        res = requests.post(BACKEND_URL, data={"Body": payload, "From": sender, "transport": "sms"}, timeout=5)
        print(f"[FORWARDED] Status: {res.status_code} | Msg: {payload}")
    except Exception as e:
        print(f"[ERROR] Failed to reach backend: {e}", file=sys.stderr)

def main():
    print(f"[*] PACT Gateway Online. Forwarding to {BACKEND_URL}")
    last_id = None
    while True:
        msgs = get_incoming_sms()
        if msgs:
            latest = msgs[0]
            msg_id = latest.get("_id")
            body = latest.get("body", "").strip()
            sender = latest.get("number", "UNKNOWN")

            if msg_id != last_id:
                last_id = msg_id
                if any(body.startswith(prefix) for prefix in PACT_HEADERS):
                    print(f"\n[RECEIVED PACT SMS] From {sender}: {body}")
                    forward_to_backend(body, sender)
        time.sleep(POLL_INTERVAL)

if __name__ == "__main__":
    main()
